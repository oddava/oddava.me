# Verification and limits

Final checks performed 11 November 2026. This is prototype verification; no Astro integration or production smoke test was requested or performed.

## Sanctioned rendering

The normal T3 preview opened a desktop local mock successfully. At mobile width, **two consecutive recorded snapshot calls failed** with the exact error:

> Preview snapshot failed: Preview automation snapshot timed out after 15000ms.

These failures are not hidden by the later successful renders. Following the user's instruction, no signed-in browser, CDP connection, cookies or lower-level session attachment was used. Local Chromium/Playwright was considered before that instruction, but **was not launched or used**. The only subsequent page renderer was the sanctioned `t3-code.html_preview` tool, called in this active thread with absolute paths to self-contained instrumented copies.

An initial HTML render rejected `min-height:100vh` because its fit-to-content frame would grow recursively. The mock shell now has an ordinary fixed minimum of 1000px, with natural content height and width media queries. This removes the circular size dependency without changing a production file.

The renderer accepts width and appearance, **not a viewport-height argument**. It returned full-document PNGs at widths **1440 and 390** for all six mock files. Exact bytes were saved from each tool result via temporary base64 files, decoded locally without transcription. Those temporary files were removed. An existing local Sharp library made deterministic **top crops at 1440×1000 and 390×844**. Cropping performs no browser automation, scaling, font replacement or repainting. Full originals remain beside the crops.

Consequently the short-name screenshots satisfy the requested image dimensions, but are **not independent 1000/844px viewport-height captures**. No height-dependent responsive behavior is claimed. The renderer also injects a small outer frame gutter; this evidence is not a promise of exact edge placement in a production browser. See `renderer-qa.json` for original dimensions, `screenshots/README.md` for all absolute paths.

## Scope and remaining checks

No Astro build, production API/feed/auth changes, real-device testing, Safari/Firefox pass, real screen-reader pass or complete accessibility audit. Browser lifecycle/reload persistence and actual keyboard traversal remain candidates for implementation-stage QA after a direction is selected. The package is self-contained; no dependency installation or paid service is needed to view it.

Production route/feed/redirect/auth/security contracts are recorded in `content-inventory.md` and were preserved by **not changing source files**. `git diff` outside the artifact folder shows only the pre-existing executable-mode change in `deploy/vps/backup.sh`.

**Artifact formatting passes:** `pnpm exec prettier --write design-directions`, followed by `pnpm exec prettier --check design-directions`, reports all matched files formatted. Prettier was run from a temporary package-manager cache because this isolated checkout has no `node_modules`; no dependency or lockfile was added to the project.

**Repository-wide formatting does not pass:** the normal `pnpm run format:check` cannot resolve the absent local `prettier-plugin-astro`. A retry uses the same single-quote/trailing-comma settings and the cached Astro plugin by absolute path, without editing root configuration. It flags **422 existing repository files**, and no `design-directions` file is among those warnings. Those source files were not reformatted because the task authorizes output only in this folder. Both attempts are preserved in `format-check.txt`; the package does not claim a green full repository pipeline.
